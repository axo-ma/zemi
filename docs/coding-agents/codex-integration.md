# Coding Agents: интеграция отчётов с Codex

## Проверенное поведение

HTML, открытый как MCP App через `zemi_probe_show`, вызывает инструменты
через `window.openai.callTool`. Пользователь подтвердил ping, открытие Excel
через Windows и открытие отдельного терминального чата с восстановленным
контекстом item/sample. Обычная вкладка `file://` не является MCP App.
Открытие файла передаётся Windows; успешный ответ не доказывает, что приложение
полностью запустилось. Запуск терминала возвращает PID; ошибки загрузки модели
показываются внутри терминала.

## Код

- `coding_agents/codex/server.py`: стабильный транспорт MCP stdio.
- `coding_agents/codex/backend.py`: обработчики, перечитываемые при каждом запросе.
- `coding_agents/codex/probe.html`: интерфейс проверки Excel и терминального чата.
- `coding_agents/codex/setup.py`: регистрация через Codex CLI.
- ZEMI CLI: `codex_install_zemi.ps1`, публичная команда `zemi codex install-zemi`.

Первый прототип лежал в `@inst/_tmp/zemi-bridge-probe`. Канонический код теперь
находится в библиотеке. Старую регистрацию marketplace нельзя считать рабочей:
плагин был установлен и включён, но сервер не появился в MCP. Рабочий способ —
прямая регистрация `codex mcp add zemi_probe`. Префикс `zemi_probe` сохранён
для совместимости с уже проверенными вызовами.

## Установка

В терминале ZEMI Component:

```powershell
zemi codex install-zemi
```

Если `codex` отсутствует в PATH:

```powershell
zemi codex install-zemi -CodexCli "полный путь к codex.exe"
```

Для выбора проверочного отчёта и Excel-файла:

```powershell
zemi codex install-zemi -CodexCli "полный путь к codex.exe" -Manifest "путь к module.chat.json" -Excel "путь к книге.xlsx"
```

Команда использует `python.defaultInterpreterPath` проекта, проверяет маркер
компонента, регистрирует и включает MCP-сервер. Настройки сохраняются в
`env.path.tmp / 'zemi-codex-integration.json'`. Повторная установка сохраняет
выбранные manifest и workbook, если новые значения не переданы.
Остальные плагины не изменяются. PATH и execution policy не изменяются.

После первой установки закончите активную работу, полностью закройте Codex,
откройте его снова и попросите вызвать `zemi_probe_show`. Команда печатает эти
шаги; она не завершает приложение автоматически.

## Изменения без постоянных перезапусков

| Изменение | Что сделать |
| --- | --- |
| Настройки выбранного отчёта, item, sample, Excel | Следующий вызов инструмента перечитает JSON |
| Логика обработчиков в backend.py | Следующий вызов перечитает Python-исходник |
| HTML, стили и кнопки | Повторно вызвать zemi_probe_show |
| Данные chat.json | Открыть новый терминальный чат |
| Команда запуска сервера, интерпретатор или server.py | Повторить установку при необходимости и перезапустить Codex |
| Имена инструментов, схема аргументов, метаданные | Может потребоваться новая сессия/перезапуск Codex |

Перечитывание backend реализовано через `runpy.run_path`, без import-кэша.
HTML читается заново при `resources/read`. Уже открытый интерфейс не обновляется
автоматически; повторное открытие получает свежий HTML. Запущенный терминальный
чат не меняет свой исходный контекст при изменении JSON-настроек.
Ни HTTP-сервер, ни новый сторонний пакет для MCP не требуются.

## Настоящие отчёты

`zemi_report_show` принимает `report`: путь к MD или HTML внутри подключённого
компонента. Пример: `.tmp/run261002-155245/spacing-v7-all.html`.
Инструмент открывает настоящий отчёт как MCP App. Его ссылки вызывают
`zemi_report_action`, который проверяет, что ссылка присутствует в текущем
отчёте. HTML-навигация остаётся внутри приложения; Excel открывается через
Windows, ячейки Items запускают `report_viewer.py --chat` для соответствующего
item/sample. Сами диапазоны, Error и ✅ являются ссылками на чат верхнего уровня.
В ячейках с деталями стрелка раскрывает детали, а кликабельный текст открывает
чат. Отдельная ссылка «Продолжить в терминале» внутри деталей не добавляется.

Все отчёты имеют MD/HTML-пару: Job, Module, Samples, Module Runs, Dataset Items,
Reproduction. Отдельные индивидуальные Run Reports не создаются. CMD остаётся
один на модуль. MD ссылается на MD и пригоден для GitHub; HTML ссылается на HTML.
CMD читает тот же HTML, который показывает MCP App. Стили, таблицы, содержание
и скрипт действий общие; скрипт выбирает доступный мост Qt или OpenAI.

HTML для MCP перечитывает Markdown и chat manifest на каждый запрос, используя
общий renderer. Сам renderer тоже загружается из исходника без import-кэша.
Транспорт и имена инструментов при дальнейшей работе остаются стабильными.
HTML-файлы на диске обновляются генератором при изменении MD; это снимки, а не
автоматически обновляемые вкладки. Для просмотра текущего снимка откройте отчёт
повторно. `inline.html` — статический вариант без инструментов для обычного
встраивания; интерактивное открытие файлов предоставляется MCP App.

`zemi_probe_show` сохраняется как диагностический интерфейс. Настройки `item`
и `sample` этого интерфейса имеют нумерацию от 1; launcher использует индексы
от 0. Произвольные команды от HTML не принимаются.
